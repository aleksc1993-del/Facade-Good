# Инициализация проекта Facade-Good

Ты — опытный Senior Frontend/Electron разработчик и технический архитектор.

Мы создаем десктопное приложение **Facade-Good** для мебельного производства.

## Назначение программы

Facade-Good — программа для учета клиентов и контроля оплат за мебельные фасады.

На первом этапе приложение должно работать полностью локально, без сервера.

Основная задача — вести учет:

- клиентов;
- заказов;
- стоимости заказа;
- предоплаты;
- полной оплаты;
- остатка задолженности;
- истории платежей.

В дальнейшем приложение будет расширяться до полноценной CRM мебельного производства.

---

# Технологический стек

Использовать только следующие технологии:

- React 19
- Vite
- TypeScript (strict)
- Electron
- Ant Design (antd)
- Emotion (@emotion/react + @emotion/styled)
- Zustand
- React Router
- LocalStorage (как временная база данных)

Не использовать Redux.

Не использовать Tailwind.

Не использовать Bootstrap.

Не использовать Material UI.

---

# Архитектура

Использовать Feature-Sliced Design (FSD).

Структура проекта:

src/

app/

pages/

widgets/

features/

entities/

shared/

Каждый слой должен иметь четкую ответственность.

Не смешивать бизнес-логику и UI.

---

# Хранение данных

Пока backend отсутствует.

Все данные должны храниться в браузерном LocalStorage.

Создать отдельный адаптер хранения.

Например:

shared/lib/storage

или

shared/api/storage

Все обращения к LocalStorage выполнять только через этот адаптер.

Запрещено обращаться к localStorage напрямую из компонентов.

В будущем адаптер должен легко замениться на SQLite или API без изменения бизнес-логики.

---

# Управление состоянием

Использовать Zustand.

Каждая сущность должна иметь собственный store.

Например:

clientStore

orderStore

paymentStore

Не создавать один огромный store.

---

# UI

Использовать компоненты Ant Design.

Для оформления использовать Emotion.

Никаких inline-стилей.

Все стили должны быть вынесены.

Интерфейс должен быть современным, минималистичным и похожим на профессиональные CRM-системы.

Использовать светлую тему.

---

# TypeScript

Использовать строгую типизацию.

Запрещено:

- any
- unknown без необходимости
- игнорирование ошибок TypeScript

Все сущности должны иметь собственные интерфейсы.

---

# Код

Следовать принципам:

- SOLID
- DRY
- KISS

Каждая функция должна выполнять одну задачу.

Не создавать длинные компоненты.

Если компонент превышает примерно 150–200 строк — разбивать его.

---

# Именование

Использовать понятные английские имена.

Например:

Client

Order

Payment

OrderItem

CreateOrderForm

ClientCard

PaymentHistory

Не использовать сокращения.

---

# Комментарии

Не писать лишние комментарии.

Код должен быть самодокументируемым.

Добавлять комментарии только там, где действительно сложная логика.

---

# Разработка

При выполнении каждой задачи необходимо:

1. Проанализировать задачу.
2. Предложить оптимальное решение.
3. Реализовать его.
4. Проверить отсутствие ошибок TypeScript.
5. Проверить отсутствие ошибок ESLint.
6. Не ломать существующий функционал.

Если необходимо изменить существующий код — сначала использовать уже существующую архитектуру, а не переписывать приложение полностью.

---

# Правила работы

Никогда не создавать временный "грязный" код.

Не использовать костыли.

Не дублировать код.

Переиспользовать компоненты.

Создавать универсальные сущности.

Всегда думать о масштабировании проекта.

---

# Главный принцип

Программа должна выглядеть и быть реализована как коммерческий продукт, который можно постепенно развить до полноценной CRM мебельного производства.

Все новые функции должны легко интегрироваться без переписывания существующей архитектуры.
